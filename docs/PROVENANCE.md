# Implementation and manuscript audit

**Identity.** The method named **Selective Router Repair (SRR)** in manuscript Section 4 and its implementation appendix is the frozen **LC-MERGE-RC r2 parent-residual, parent-reliable, clipped** candidate builder. The public rename does not turn the method into OPFR, add trajectory refresh, or change the optimization objective.

| Manuscript rule | Public implementation | Original experimental implementation |
| --- | --- | --- |
| Parent-generated continuations; base/source/parent traces | `srr.cache.generate`, `srr.build.capture_rows` | `run_external_opfr.generate`, `build_lc_merge_rc_candidate.capture_rows` |
| Likelihood-weighted centered source/base profile, activity, split-stable pair selection | `srr.build.prompt_profile`, `split_summary`, `candidate_edges`, `select_edges` | Identically named functions in `build_lc_merge_rc_candidate.py` |
| Source-parent pair residual, source-base clipping, positive source-over-parent NLL gate | `srr.build.build_layer_system` | Identically named function in `build_lc_merge_rc_candidate.py` |
| FP64 PCG weighted ridge; regularizer averaged over **all** train tokens | `srr.solver.batched_weighted_functional_pullback` | `nf_terrd_functional_solver_retry04_20260728.py` |
| Equal/opposite pair writeback, fixed scale, final five routers, BF16 scope check | `srr.build.pair_row_update`, `srr.build.main` | `build_lc_merge_rc_candidate.main` |

The source snapshot used for this release was `build_lc_merge_rc_candidate.py`, SHA-256 `05e5a53b8545450ed8bac88802efc10ca346cd6bc1db5b187a80d1dd0161e718`, and its solver was `nf_terrd_functional_solver_retry04_20260728.py`, SHA-256 `ff9a9e610f31cefd16bf16aed175c667e0ac5ae87f9d9d9aae562b51c3425be2`. The experimental cross-architecture driver called those same pair-selection and fitting functions. The public package removes server-specific absolute paths and the dependency on the old OPFR runner, exposes a frozen JSON protocol, reconstructs native router logits for DeepSeek-style gates, and adds a standalone parent-trajectory cache generator and overlay tool. These are packaging and model-I/O changes, not a change to the SRR mathematical rules.

The frozen cross-architecture LC-MERGE-RC protocol specified: final five routers; 2 pairs per role; prompt sign consistency `0.75`; minimum route activity `0.002`; likelihood temperature `0.5`; relative ridge `0.001`; PCG maximum iterations `4096`, tolerance `1e-6`, residual refresh interval `4096`; update scale `0.0625`; seed `2026091101`; and greedy parent generation capped at 96 new tokens. These are reflected in the example SRR config. The calibration prompt set, source checkpoints, merge parent, architecture-specific batch size, and exact evaluation environment are separate inputs and are not included here.

**Numerical identity and boundaries.** `center(log_softmax(z_source)-log_softmax(z_base))` equals `center(z_source-z_base)` in real arithmetic; the code retains the experimental log-softmax implementation. The ridge data term is a weighted **sum**. Its regularizer uses the weighted parent-hidden squared norm divided by the number of all pooled training tokens, including zero-weight tokens. The fixed scale is not selected with benchmark feedback. The covariance-based router-logit displacement is diagnostic only; no projection against the reference `B_p` occurs. `srr.overlay` casts candidate router weights into the parent model's runtime dtype and checks the BF16 changed-router scope; large benchmark claims cannot be inferred from this code release alone.

**Not included.** Manuscript figures or historical benchmark tables are not relabelled here. Any figure produced by a different checkpoint or older OPFR run must retain its actual provenance; sharing the SRR name would not make it an SRR checkpoint. The manuscript itself was not edited for this release.
